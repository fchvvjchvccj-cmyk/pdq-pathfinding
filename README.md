# PDQ Pathfinding

简体中文 · [English](README.en.md)

PDQ（势差双端队列）用一个双端队列在网格上找最短路。适用条件很简单：每次只能向上、下、左、右走一格，每步代价都是 1，搜索过程中地图不变。这个仓库里有 Python 实现，也有和 BFS、堆 A*、桶队列 A* 的对照实测。

## 为什么一个双端队列就够了？

设 `h` 是到终点的曼哈顿距离。四方向移动一步，`h` 只会减少 1 或增加 1。把边 `u → v` 的代价改成 `(1 + h(v) - h(u)) / 2`，就只剩下 0 和 1 两种权重：搜到更短的走法时，权重 0 的邻居放队首，权重 1 的放队尾。

沿一条路径把这些代价加起来，中途的 `h` 会抵消，最后得到的是步数的一半，加上一个由起终点决定的常数。对同一对起终点，重算代价后的最短路也就是原来步数最少的路。这就是 PDQ 可以用 0–1 BFS 来做的原因。

原版 PDQ 和仓库里的桶队列 A* 在实测中返回了相同的路径，扩展节点数也一样。地标版使用的是已有的 ALT 思路。

## 实测表现

在 15 张地图、240 个查询的复测里，`pdq_fast` 的逐查询配对加速比中位数，相对原版 PDQ 是 **1.43×**，相对同优先级时优先较大 `g` 的堆 A* 是 **2.52×**，相对桶队列 A* 是 **1.63×**。计时包含搜索和完整路径还原；这些数字只代表这组地图、查询和 Python 实现。

地标版在两张迷宫图上大约查 11 次和 12 次就能摊平预处理时间，参照的是 `pdq_fast`。但把 15 张地图都算上，每张图查 16 次时，预处理加查询的总成本仍是 `pdq_fast` 更低。
