# PDQ 优化复测

快版适合直接用：不做地图预处理，在 240 个查询里有 237 个比原版 PDQ 快。地标版在迷宫里能省下更多搜索时间，但得先为这张地图算好地标距离。这一轮除了量查询有多快，也把这笔开销单独算了一遍。

## 怎么测的

在 Windows 11（10.0.22631）和 Python 3.14.7 上，用种子 20261103 选取与[原始实测](../results/report.md)相同的 240 个查询：15 张图，每张 16 个。原版 PDQ、高 `g` 优先的堆 A*、桶队列 A* 和 BFS 都和新版本一起重测。每个实现对每个查询先预热，再随机交错计时 5 次，共 8,400 次，计时期间关闭循环垃圾回收。

单次查询计时从数组初始化或更新工作区标记开始，到还原出完整路径为止。工作区版和地标版的地图预处理另计，在批次比较中加回。12,484 个小图问题和全部实测查询都通过了正确性检查；另外核对了 18,382 条边的启发值差的绝对值为 1，并检查了工作区标记溢出和更换终点后的复用。

## 这次改了什么

**快版**先试两条简单的折线：先横后竖、先竖后横。只要有一条能走通，长度就恰好等于曼哈顿距离，可以直接返回。两条都走不通时，再按原版 PDQ 的顺序搜，返回的路径和扩展量也与原版一致。搜索循环省掉了通用模式判断，不再为每个节点临时构建邻居元组。试走折线的开销计入查询时间和 `scanned`。

**工作区版**保存地图快照、连通分量和查询数组。起点和终点不在同一个连通分量，直接返回无解。反复查询时用标记区分每次写入的数组项，不缓存上次的答案或启发值。

**地标版**在最大的连通分量里，用最远点采样选最多四个地标，每个地标各跑一次 BFS。查询时取曼哈顿距离和各地标距离差的绝对值 `|d(地标, u) - d(地标, t)|` 中的最大值。这个下界沿用了 [ALT 的思路](https://www.microsoft.com/en-us/research/publication/computing-the-shortest-path-a-search-meets-graph-theory/)。四方向网格上的各项下界都是一致的，奇偶性也相同，所以相邻格子的启发值仍相差 ±1，可以继续用双端队列找最短路。其他连通分量只用曼哈顿距离。

## 使用时的限制

地图变了就要重建 `PreparedPDQ`；并发查询时，每个线程用自己的实例。`buffer_bytes` 只统计长期保留的数组和网格缓冲区，预处理用的临时数组、搜索队列和 Python 进程的峰值内存都不在这个数字里。

复测没有覆盖 JPS4、KIA*、带权地图、斜向移动、动态障碍、跨机器比较或完整公开数据集。需要看每次计时，可以查[原始记录](raw.json)或[逐查询数据](queries.csv)。
